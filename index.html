What is Kerberos?

Kerberos is a trusted third-party network authentication protocol developed at MIT. Named after Cerberus, the three-headed dog of Greek mythology that guarded the underworld, it uses three "heads" — the Client, the Authentication Server and the Ticket Granting Server — to guard your network.

🎫

Ticket-Based Access

Instead of sending passwords over the network, Kerberos issues encrypted tickets. A client proves its identity once and receives a Ticket Granting Ticket (TGT), which is reused to access many services without re-typing passwords.

🔑

Symmetric Key Crypto

Kerberos relies on secret-key (symmetric) cryptography. Early versions used DES, modern Kerberos v5 uses AES. Only trusted parties share the secret keys — the KDC never transmits them.

⏱️

Timestamps & Anti-Replay

Every message carries a timestamp. Servers reject messages older than the allowed clock skew (typically 5 minutes), defeating replay attacks where hackers try to reuse captured tickets.

🏛️

Key Distribution Center

The KDC is the heart of Kerberos, combining the Authentication Server (AS) and Ticket Granting Server (TGS) in one trusted machine. It holds the master secret key of every principal in the realm.

🛡️

Mutual Authentication

Kerberos doesn't just verify the client — the client also verifies the server! The service ticket contains an encrypted timestamp that proves the server truly holds the shared secret key.

📜

Kerberos v5 — RFC 4120

The current standard, Kerberos Version 5, defined in RFC 4120, adds cross-realm authentication, stronger encryption options, and better ticket forwarding — used today in Windows Active Directory and Hadoop.

The 6-Step Authentication Flow

This is the exact sequence you will rebuild in Game 2! Memorise the journey of a message from Client → AS → TGS → Service.

1

Client → Authentication Server (AS)

The user logs in. The client sends its ID and a nonce (random number) to the AS, requesting a Ticket Granting Ticket.

⬇ encrypted with the client's secret key
2

AS → Client

The AS verifies the user in its database and replies with a TGT plus a session key — encrypted with the client's secret key derived from the password + salt.

⬇ TGT presented to the TGS
3

Client → Ticket Granting Server (TGS)

For each new service, the client sends the TGT plus an authenticator (ID + timestamp) encrypted with the TGS session key.

⬇ service ticket issued
4

TGS → Client

The TGS decrypts and validates everything, then issues a service ticket for the target application server, plus a new service session key.

⬇ service ticket presented
5

Client → Application / Service Server

The client presents the service ticket and a fresh authenticator encrypted with the service session key to the application server.

⬇ mutual authentication complete
6

Service → Client (Mutual Auth)

The service decrypts the ticket, and sends back the client's timestamp + 1 encrypted with the session key. The client now trusts the service too. Secure session begins! 🎉

📖 Kerberos Glossary

The 16 essential terms every cyber-security student must know.

TermMeaning
KDCKey Distribution Center — trusted third party holding all secret keys; contains AS + TGS.
ASAuthentication Server — verifies the user's identity and issues the TGT.
TGSTicket Granting Server — exchanges TGTs for service tickets.
TGTTicket Granting Ticket — proof of identity used to obtain service tickets.
Service TicketEncrypted credential authorising access to one specific application server.
AuthenticatorClient ID + timestamp encrypted with a session key, proving the ticket is used live.
Session KeyTemporary symmetric key shared between two parties for one conversation.
PrincipalA unique named identity in Kerberos (user, host or service), like user@REALM.
RealmAn administrative domain of Kerberos principals, written in UPPERCASE (e.g., EXAMPLE.COM).
SaltExtra data (usually realm + username) mixed into the password before key derivation.
NonceA random number used once, preventing replay of the initial authentication request.
Clock SkewMaximum allowed time difference (default 5 min); tickets older than this are rejected.
Replay AttackAttacker re-sends a captured message; defeated by timestamps and nonces.
Mutual AuthenticationBoth client and server prove their identities to each other.
Ticket LifetimeHow long a ticket stays valid before it must be renewed or re-issued.
AES / DESSymmetric encryption algorithms — DES in legacy Kerberos, AES in modern Kerberos v5.
